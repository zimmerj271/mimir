# Context serialization and memory-ingestion contract v1

- `policy_version = mimir-context-v1`. Build system/developer guidance from trusted static application configuration only; inject user prompts, message history, memory snippets, project instructions and tool results as individually tagged untrusted content blocks. Escape delimiter tokens by JSON serialization; never string-concatenate raw content into instructions.
- Each block is `{ "kind": "memory|history|project|user_input", "source_id": "...", "text": "...", "trust": "untrusted" }` in a JSON array, with deterministic order: static system policy, project instructions, selected memories sorted by score-desc/id-asc, chronological exact message revisions, current user input. Message provenance stays visible to the assembler. When token budget insufficient, drop least relevant memories first, then oldest non-essential history; keep system policy and current user input, otherwise typed `context_budget_exceeded`.
- Memory ingestion event only after atomic success of user-revision + final assistant-revision pair: `event_version=1`, `user_id`, optional `project_id`, `conversation_id`, `user_revision_id`, `assistant_revision_id`, `run_id`, `committed_at`, `provider_config_id`. This payload is the canonical unit, never a loosely defined 'turn'. Deduplication key = `(user_revision_id, assistant_revision_id, provider_config_id)`; outbox at-least-once, idempotent adapter.
- `MemoryResult` typed fields: `memory_id`, `revision_id`, `text`, `score` (0..1), `source_revision_ids[]`, `provider_config_id`, `project_id` nullable. Callers must validate returned provenance under current owner in PostgreSQL before adding text to prompt. Provider internals stay behind MemoryService.
- No raw prompt bodies in logs, crash journals, telemetry attributes or error responses. Context diagnostic records may store selected IDs/token counts and policy version but not full assembled prompt.
